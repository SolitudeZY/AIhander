# 远程会话持久化与脱敏接口设计

> 2026-09-22 补充：新版 Bash 已增加可选逐命令耗时及真实退出码，详见 [WebShell 命令结果最小升级说明](WebShell命令结果最小升级说明.md)。下文 `submitted`、耗时及退出码为 null 的约定继续适用于旧 Agent、非 Bash 及未启用采集的会话。

日期：2026-09-22。状态：后端代码已实现并完成本地测试，迁移脚本和 ARM64 Agent 构建已提供；尚未执行实际数据库迁移、板端部署或前端页面联调。本文描述当前实现契约。

## 1. 需求与已确认范围

项目需求：

> 历史记录至少显示操作人、会话状态、开始与结束时间、会话时长和命令明细。敏感命令和参数按安全规则脱敏。

本次已确认保留完整交互终端，支持 Bash、vim、top 等交互操作；实施账号权限隔离和脱敏会话记录，不承诺逐命令执行前审查，也不把终端改成只读命令白名单执行器。

业务入口、菜单和操作权限继续由现有管理平台负责。本次不新增登录接口、Token、角色体系、鉴权端口或独立服务。沿用当前平台 HTTP/WebSocket 连接和既有用户信息，仅用于关联真实操作人。前端的入口控制不能替代 Linux 的执行权限限制；后者通过终端账号和文件权限实现。

完整 PTY 不提供可靠的逐命令边界。历史“命令明细”在本方案中表示可识别的已提交输入及其上下文，不能承诺每行都是一条实际执行的 Shell 命令。无法识别的交互内容明确标注，不推测成功、失败、耗时或退出码。如果验收要求每条实际命令都有准确退出码，本方案不满足，需要另行确认 Shell 集成或结构化执行协议，不能以猜测数据代替。

## 2. 当前实现与最小改动

当前链路：浏览器 → Device-Management Node Terminal Gateway → Go Cloud → Agent PTY。输出沿原链路返回。

旧版 `edge_remote_session` 只保存会话和操作人信息，未保存终端输出；Node Gateway 曾记录未经完整脱敏的输入摘要。本次已删除该摘要日志路径，增加脱敏录制和详情 `commands`。前端历史列表数据转换仍需保留详情字段，并接入详情查询。

本次采用以下改动：

| 位置 | 改动 |
|---|---|
| Node `terminalGateway.js` | 复用当前会话生命周期，增加有界录制、脱敏与串行保存；移除原始输入摘要日志 |
| 现有 `EdgeRemoteSession` 模型 | 增加一个可空 JSONB 字段 `recording`，不新建录制表或逐命令表 |
| 现有会话详情接口 | 返回录制摘要、输入明细和终端记录；会话列表只返回摘要 |
| Agent Linux PTY 启动 | 增加可选终端运行用户，仍使用现有 PTY，不增加命令执行服务 |
| 前端（交接项，本次不修改） | 点击历史项查询详情，展示输入明细、脱敏终端记录和录制完整性 |

Go Cloud 继续转发原有终端消息。输出持久化和脱敏放在已有业务会话及操作人信息的 Node Gateway，不在 Go Cloud/Agent 重复建设业务会话库。

## 3. 现有接口扩展

以下 HTTP 路径相对于管理平台已有 API 前缀；例如部署前缀为 `/api/v1` 时，在这些路径前加 `/api/v1`。`sessionId` 是管理平台 `edge_remote_session.id`，不是 Cloud 的字符串会话 ID。

### 3.1 会话列表

```http
GET /edgeCloud/devices/{deviceId}/remote-sessions?page=1&pageSize=20
```

保留现有 `page`、`pageSize`、`operatorId`、`status`、`startTime`、`endTime` 参数和 `{count, rows}` 返回结构。`pageSize` 默认 10、最大 100。保持现有时间筛选语义：`startTime` 为开始时间下界，`endTime` 为结束时间上界。

保留现有字段：`id`、`cloudSessionId`、`projectId`、`projectName`、`deviceCode`、`deviceName`、`operatorId`、`operatorName`、`purpose`、`status`、`startedAt`、`endedAt`、`durationSeconds`、`endReason`、`createdAt`。

每条记录新增 `recordingSummary`，不在列表返回正文：

```json
{
  "recordingSummary": {
    "available": true,
    "state": "complete",
    "inputCount": 2,
    "eventCount": 6,
    "lastSavedAt": "2026-09-22T07:10:05.000Z",
    "truncated": false
  }
}
```

### 3.2 会话详情

```http
GET /edgeCloud/remote-sessions/{sessionId}
```

保留现有会话字段，新增 `recordingSummary`、`commands`、`recording`。首版采用单会话有界返回，不新建查询路由。列表查询在数据库层排除 `recording` 正文，避免查询 100 个会话时一次取出全部录制数据。

下面是详情返回的节选；实际响应保留其余现有字段：

```json
{
  "id": 123,
  "cloudSessionId": "aabbccddeeff00112233445566778899",
  "deviceCode": "ee:4d:fe:90:97:3d",
  "operatorId": 8,
  "operatorName": "张三",
  "status": "ended",
  "startedAt": "2026-09-22T07:00:00.000Z",
  "endedAt": "2026-09-22T07:10:00.000Z",
  "durationSeconds": 600,
  "endReason": "browser_closed",
  "recordingSummary": {
    "available": true,
    "state": "complete",
    "inputCount": 1,
    "eventCount": 2,
    "lastSavedAt": "2026-09-22T07:10:00.000Z",
    "truncated": false
  },
  "commands": [
    {
      "id": 1,
      "submittedAt": "2026-09-22T07:00:03.000Z",
      "command": "uname -a",
      "kind": "input",
      "status": "submitted",
      "durationMs": null,
      "exitCode": null,
      "redacted": false,
      "eventSeq": 1
    }
  ],
  "recording": {
    "version": 1,
    "format": "text",
    "shellExitCode": null,
    "events": [
      {
        "seq": 1,
        "time": "2026-09-22T07:00:03.000Z",
        "direction": "input",
        "text": "uname -a",
        "redacted": false
      },
      {
        "seq": 2,
        "time": "2026-09-22T07:00:03.100Z",
        "direction": "output",
        "text": "Linux kickpi 6.1.75 aarch64 GNU/Linux\n",
        "redacted": false
      }
    ]
  }
}
```

`commands` 是同一份录制中输入记录的展示投影，不再存第二份命令实体。`eventSeq` 定位输入在终端记录中的位置，后续输出属于整个会话，不能保证都由这一条输入产生。后台任务可能在其他命令执行时输出。

| 字段 | 约定 |
|---|---|
| `commands[].id` | 当前会话内的输入序号，不作为执行任务 ID |
| `submittedAt` | 网关收到提交输入的时间，不是执行端开始时间 |
| `command` | 脱敏后的可识别输入；无法可靠还原时为 `[交互输入未解析]` 或 `[输入内容已隐藏]` |
| `kind` | `input` 为可识别提交输入；`interactive` 为编辑/补全/交互程序等无法还原的输入 |
| `status` | 固定为 `submitted`，仅表示已向上游转发；不代表命令成功 |
| `durationMs` / `exitCode` | 本模式下为 `null`，前端显示 `—`，不得使用 0 填充 |
| `events[].seq` | 网关生成的会话内递增序号，涵盖输入和输出，与 Cloud 输出块 `sequence` 不同 |
| `events[].time` | 网关接收时间，统一为带时区的 ISO 8601 |
| `events[].text` | 脱敏纯文本，清理 ANSI/OSC 控制序列；不作为 HTML 渲染 |
| `recording.shellExitCode` | 仅接收到 `exited.exit_code` 时填写，表示整个 Shell 退出码；断线时为 `null` |

`status` 继续使用会话级 `active`、`ended`、`abnormal`，不根据某条命令的输出判断。录制是否完整由 `recordingSummary.state` 表达，不能把会话正常结束等同于录制完整。

### 3.3 录制状态与旧数据

| `recordingSummary.state` | 含义 |
|---|---|
| `unavailable` | 升级前的旧会话没有录制，`available=false` |
| `recording` | 会话仍在录制，接口返回已保存的部分 |
| `complete` | 会话已结束，最终录制保存成功，未因故丢失或截断 |
| `partial` | 达到上限、服务异常中断或保存失败，只能返回已有部分 |

旧数据返回 `commands=[]`、`recording=null`，不得伪造旧命令及输出。`truncated=true` 表示达到容量上限；`partial` 也可能来自异常中断，此时不一定是截断。

HTTP 状态保留现有参数错误 400、未找到会话 404。新增的录制读取故障返回 500 和通用错误消息，不能伪装成“没有历史数据”。

### 3.4 实时 WebSocket

继续使用管理平台已有 `/terminal/connect?device_id=...`，不新增端口。原消息不变：客户端 `input`、`resize`、`close`；服务端 `opened`、`output`、`exited`、`error`。现有认证帧处理保持既有约定，不新增共享密钥或登录流程。

实时输入输出继续传输原始终端数据，保证交互程序可用；脱敏作用于持久化副本、历史查询和服务日志，不改写用户实际执行的命令，也不静默修改实时 Shell 输出。

仅新增一个必要的故障通知：录制不可用或中途失败时，通过原有 `error` 类型发送 `code=RECORDING_UNAVAILABLE`，提示“会话记录不可用，终端已断开”。已接受命令是否完成必须标为未知，断开不代表执行回滚。

## 4. 首版脱敏规则

以下规则已实现；业务若有特定凭证字段应补充示例。首版发现敏感键、凭证 URL 或敏感命令时保守隐藏整行，不只替换参数值；无法可靠划分的续行隐藏至下一次可识别的 Shell 提示符，空行不作为敏感值结束标记。脱敏不是命令审批，不改变执行权限。

| 场景 | 当前规则 | 历史示例 |
|---|---|---|
| 命名参数/赋值 | 不区分大小写识别 `password`、`passwd`、`pwd`、`token`、`access_token`、`refresh_token`、`secret`、`api_key`、`apikey`、`client_secret`（兼容相应连字符写法），处理 `--key value`、`--key=value`、环境赋值、JSON 键值 | 输入为 `[输入内容已隐藏]` |
| HTTP 凭证 | 含 `Authorization`、`Proxy-Authorization`、`Cookie`、`Set-Cookie` 的行整体隐藏 | 输出为 `[终端片段已隐藏]` |
| URL 凭证 | 含 URL userinfo 或敏感查询参数的行整体隐藏 | `[终端片段已隐藏]` |
| 私钥 | 从 PEM 私钥 BEGIN 到 END 整段隐藏，覆盖多行及跨消息片段 | `[终端片段已隐藏]` |
| 密码输入 | 识别密码/passphrase 提示后，隐藏后续对应输入；不保存逐按键原文 | `[输入内容已隐藏]` |
| 敏感命令 | `passwd`、`chpasswd`、`sshpass` 等凭证操作的输入正文整体隐藏 | `[输入内容已隐藏]` |
| 普通诊断输入 | 对可识别的 `uname -a`、`uptime`、`pwd`、`df -h` 等保留脱敏后的文字 | `uname -a` |
| 无法判断的输入 | 补全、光标编辑、历史选择或交互程序输入不拼接成看似准确的命令；按不确定输入隐藏或标记 | `[交互输入未解析]` |

命令名称出现在此表只影响历史脱敏，不是执行允许/禁止名单。`pwd` 作为单独命令不脱敏，作为凭证键赋值时才隐藏其值。

输入按提交换行形成记录。只有观察到常见 `$ ` / `# ` Shell 提示符后的普通输入才保留文本；补全、光标编辑、历史选择、无法识别的提示符和交互程序输入保守隐藏，相关回显也隐藏。提示符识别是展示启发式，不是逐命令协议。输入尚未提交就断线时不生成 `submitted` 记录。输出清除 ANSI/OSC 控制序列、保留普通文本和制表符；不能作为原始终端录屏重放。

未完成片段最多保留 5 秒，超时即丢弃原文并隐藏后续未决内容；关闭时未完成的输出尾部只保存占位符。容量上限触发后停止录制，实时交互仍继续。任意程序输出的无标签秘密、未知密码提示或伪造提示符无法被这些规则完全识别。

实现约束：

1. 脱敏在写数据库、应用日志之前执行。删除现有把 `input.slice(0,500)` 直接写入 `SystemLog` 的路径，系统日志只保留会话关联信息和录制状态。
2. 输入、输出都需要流式状态：消息可能在 UTF-8 字符、参数名、参数值或私钥中间切开。不能对单个 WebSocket 包独立正则替换后直接保存。
3. 不完整的敏感字段或未结束私钥只允许在有界内存中等待；超限、超时或断线时保守隐藏未决部分，不能原样冲刷到数据库。
4. 控制序列处理必须跨分片；无法安全还原的部分隐藏。历史文本用于阅读，不承诺原样重放 vim/top 的屏幕状态。
5. 任意程序都可能输出没有标签的秘密；自动规则无法保证识别全部内容。未知密码提示、交互输入和多行敏感配置必须纳入测试，不能把“匹配了几个正则”描述成完整审计安全能力。若要求任何秘密绝不落库，需要进一步限制录制内容或引入明确的敏感输入标记，届时先提示用户，不擅自扩大设计。

## 5. 持久化和容量

首版只扩展现有表，实际迁移脚本为 `Device-Management/script/2.0.0/2.add_remote_session_recording.sql`，核心语句如下：

```sql
ALTER TABLE public.edge_remote_session
  ADD COLUMN IF NOT EXISTS recording jsonb;
```

`recording=NULL` 表示旧数据无录制。新对象保存版本、录制状态、最后保存时间、截断标志、Shell 退出码及事件数组，接口从中投影摘要和 `commands`。

首版上限：单会话序列化后的录制 JSON 最多 1 MiB、事件最多 5000 条、单事件文本最多 8 KiB；超过限制保留已保存的前缀，置 `partial` 和 `truncated=true`，不静默丢失后仍声称完整。输入/输出单行缓冲超过 8 KiB 时同样停止录制并标记截断。对持续运行的终端可以继续交互，但历史页面必须展示截断提示。容量统计按 UTF-8 字节执行。

按会话串行更新同一字段，每 1 秒或累计 16 KiB 脱敏事件数据触发保存，正常关闭执行最终保存。最多一个数据库写入进行中，新事件合并到当前有界文档，不逐帧排队；保存中新增的数据在后续周期或最终保存中写入。连接建立前的待转发队列最多 32 条、总计 64 KiB，超限关闭；WebSocket 发送积压超过 1 MiB 也关闭并标为异常。

创建会话及首份录制记录失败时，不开放可输入的终端；保存中途失败时关闭本次终端，停止接受新输入，发送录制不可用通知。数据库故障期间只能保留已提交的记录，不声称失败通知也一定落库。

网关启动时，对该实例遗留的未结束会话标记异常中断，录制为 `partial`；异常前仍在内存的最后一批内容无法恢复。现有实现按单实例管理活动会话，此方案沿用该部署假设，不新增分布式会话协调；若实际部署多副本，不能批量结束其他实例会话，需要先核对实例归属方案。

启动恢复会更新该数据库中的所有未结束远程会话，因此本版本仅适用于单实例 Gateway。恢复查询失败时拒绝本进程的新终端连接；修复数据库/完成迁移后应重启 API。新增异常原因包括 `recording_failed`、`gateway_restart`、`buffer_limit`，列表的 `status=abnormal` 筛选同步覆盖这些原因。持久化只记录经过此 Node Gateway 的连接，直接访问 Go Cloud 自带终端的连接不进入管理平台历史。

## 6. 独立 Linux 用户隔离

建议账号 `edgeops`，Agent 服务仍以 `kickpi` 运行。Terminal 只在创建 PTY 子进程时切换到 `edgeops`，不要把 Agent 主进程改回 root。

| 项目 | 默认建议 |
|---|---|
| 用户组 | 不加入 sudo、adm、systemd-journal、docker 等扩大权限的组 |
| 重启/关机 | 不为 edgeops 安装 Polkit 放行规则；现有 kickpi 重启授权不扩展到 edgeops |
| 写入目录 | 仅自身 home/工作目录；不额外开放模型、部署目录和业务配置写权限 |
| 日志读取 | 需要时仅授权具体业务日志，不授予所有系统日志读取权限 |
| Shell | 仍为真实 Bash/PTY，命令能否读写或执行由操作系统权限决定 |
| 网络与公共文件 | 新账号不是容器：世界可读文件、默认可用的网络和 /tmp 等仍按系统策略可访问 |

Agent 的现有 `terminal` 配置新增可选字段 `run_as_user`：

```json
{
  "terminal": {
    "enabled": true,
    "shells": ["/bin/bash"],
    "max_sessions": 2,
    "run_as_user": "edgeops"
  }
}
```

该字段已实现。设定后只允许服务端配置的目标账号；客户端不能指定账号。隔离模式仅接受 `/bin/bash`，启动失败不尝试其他 Shell，不回退到 kickpi 或 root。未配置时保留既有行为，这是兼容模式，没有终端用户隔离。Windows 配置该字段会返回不支持错误。若 sudo 进程已经启动后才发现权限或启动入口错误，可能先收到 `opened`，随后收到错误和退出消息；此时也不会启动兼容模式 Shell。

普通用户 kickpi 无法任意 setuid，部署隔离模式需要一次性安装限定的系统切换配置。仓库提供 `script/firmware-terminal-shell` 和 `script/firmware-terminal.sudoers.example`：仅允许 kickpi 无交互地以 edgeops 执行 `/usr/local/libexec/firmware-terminal-shell`，且不接受参数。启动入口固定使用 `/home/edgeops`、清空环境并启动 `/bin/bash --noprofile --norc -i`。Agent 检查目标 UID 非 root 且不同于自身，启动文件及所有父目录必须由 root 拥有、不可被组/其他用户写入且不是符号链接。不能放行任意目标用户、任意 root 命令或保持全部 Agent 环境。这是 Linux 账号切换配置，不是平台登录/角色鉴权设计。

单独建账号仍不能遮住世界可读的凭证文件。部署前必须核对 Agent 状态文件、业务配置、私钥和环境文件的实际权限；按明确文件范围收紧或授权，不能递归 chown 整个业务目录。需要读取的业务日志路径和额外目录权限仍由部署方确定。本次未创建系统用户或修改板子配置。

## 7. 前端接入要求

1. 历史会话列表展示现有操作人、状态、开始/结束时间和时长。未结束的 `endedAt=null` 显示 `—`。
2. 点击具体历史项调用现有会话详情接口，不直接把列表对象当详情；数据转换保留新增字段。
3. “命令明细”展示 `commands` 的时间、脱敏输入和输入类型。不能把 `submitted` 翻译为成功，不再强制要求逐命令耗时和退出码；若保留这两列，显示 `—`。
4. 增加“会话输出”区域展示脱敏纯文本。可从某条输入的 `eventSeq` 定位上下文，但不将后续全部文本标成该命令的专属输出。
5. `unavailable` 显示“该历史会话未录制”；`partial`/`truncated` 显示对应提示。录制不存在不等于用户没有输入命令。
6. 页面原有“敏感命令均已审查”“越权命令会被设备直接拒绝”等说明应改为实际约定：按系统账号权限执行、历史按规则脱敏。本方案不提供逐命令审批。
7. `toSession()` 需要保留详情的 `commands`、`recording`、`recordingSummary`；历史弹窗不能继续只使用列表对象。列表标题使用已有 `purpose`，为空才回退到 `运维会话 #id`，后端不增加第二个标题字段。

## 8. 实施顺序与验收

代码实现完成。部署顺序为：停止单实例管理 API → 执行上述 SQL 迁移 → 发布并重启 Node API → 前端按第 7 节接入详情 → 如启用账号隔离，再部署新版 Agent 和限定的系统账号配置。Node 部分是现有 JavaScript 源码，无新增 npm 依赖或单独构建步骤。Go Cloud 终端协议未改变，无需为录制重新构建，也不增加端口。

新版 Agent 还修复了 PTY 的 UTF-8 字符被读取边界切开后经 Cloud 转 JSON 产生乱码的问题，最多保留 3 个未完成字节。合法中文/emoji 跨块保持完整；非法 UTF-8 或 EOF 时未完成字符仍转换为 Unicode 替换字符 `U+FFFD`。旧 Agent 可以接入录制，但要获得此修复和账号隔离必须升级 Agent。

| 验收项 | 预期 |
|---|---|
| 普通交互 | 现有终端输入、尺寸调整、vim/top 和关闭行为正常 |
| 历史持久化 | 关闭页面、重新登录后可查询已保存的脱敏输入和会话输出 |
| 操作人 | 复用当前会话解析出的真实平台用户，不能串用全局操作人；无法取得身份时不伪造姓名 |
| 分片脱敏 | 密码、URL 凭证、Authorization、UTF-8 和私钥跨消息分片后不泄漏到数据库或应用日志 |
| 交互歧义 | 历史选择、补全、多行输入、编辑器按键不被编造成成功执行的命令 |
| 有界存储 | 持续输出触发上限后有明确 partial/truncated 标志，内存和队列不持续增长 |
| 数据库失败 | 建立阶段拒绝输入；运行中失败提示并关闭终端，已执行内容不宣称已回滚 |
| 异常中断 | 已保存部分保留，恢复后标记 partial/异常结束，不编造丢失的尾部 |
| 账号隔离 | PTY 内 `id` 显示 edgeops，写业务程序/配置和执行系统重启被实际权限拒绝 |
| 隔离失败 | 目标账号不存在或切换失败时返回错误，不回退到 Agent 用户 |
| 兼容旧记录 | recording 为 NULL 的旧会话仍能查询元信息，明确无录制 |

## 9. 部署前待核对事项

- 本文第 4 节脱敏规则及字段名称是否覆盖实际业务凭证；当前按保守隐藏不确定输入设计。
- 本文“命令明细=输入明细+会话上下文”的语义是否满足产品验收，不包含逐命令真实退出码。
- edgeops 需要读取的具体日志路径、可写工作目录及网关是否单实例部署。
- 1 MiB/5000 事件的首版会话上限是否满足常用运维时长；如需长时完整录屏，应重新评估存储方式，不能把无界日志塞进单行 JSONB。

这些是规则和部署范围的核对项，不要求增加新的平台鉴权设计。平台继续使用现有用户信息，无法解析操作人时为 null，不回退到全局最近操作人的 ID。尚未部署新版服务，因此旧环境不会自动产生历史录制，过去未保存的命令/输出无法补回。
