# Agent 构建说明

独立 Go Cloud 已退役，管理端直接运行 Device-Management Node API。迁移步骤见 [Node-Agent迁移计划](../../Device-Management/doc/Node-Agent迁移计划.md)。

以下命令在 Windows PowerShell 中执行，Go 要求以 `go.mod` 为准（Go 1.26.0，推荐工具链 1.26.5）。

```powershell
Set-Location 'E:\Python_Prj\landSlide\ZY\rk3576_deploy\AIhander\FirmwareUpgrade'
go test ./...
go vet ./...
& '.\doc\构建.bat' agent
```

不带参数或参数 `all` 均只构建 Agent；旧参数 `cloud` 返回错误。输出为 `bin/test/agent.exe` 和 `bin/test/agent-linux-arm64`。第二个参数指定输出目录；相对目录从项目根目录计算。

```powershell
& '.\doc\构建.bat' agent '.\bin\agent-build'
```

批处理使用 `CGO_ENABLED=0`，显式选择平台，不继承之前的交叉编译设置。任一步失败即停止；不会自动停止服务或执行设备重启。若输出程序正在运行，指定另一个输出目录。

## Linux ARM64 部署

RK3576 使用 Agent ARM64 二进制。设备配置的 `server_url` 填 Node API 根地址（如 `http://10.8.30.64:4700`），不含 `/api/v1`。保留原设备状态文件和本地数据库，完成 Node 身份迁移后再切换设备地址。

```sh
chmod +x ./agent-linux-arm64
./agent-linux-arm64 -config ./configs/agent.example.json
```

使用 systemd 时确认 `WorkingDirectory`、配置路径、运行账号及下载目录与现有部署一致；仓库保留 `script/agent_watchdog.service`。是否启用远程重启须按既有系统授权配置，不因后端迁移而自动开启。

Agent 0.4.1 新增按服务器 URL 保存认证状态，升级及回退时需兼顾状态格式。首次升级保留旧 `state_file`，注册成功后自动迁移并生成 `.legacy.bak`；日后切换开发/测试服务器只需修改 `server_url` 并重启，详细步骤见 [Agent 多服务器认证状态](Agent多服务器认证状态.md)。

## 其他调试入口

```powershell
New-Item -ItemType Directory -Force '.\bin\test' | Out-Null
go build -buildvcs=false -trimpath -o bin/test/setup.exe ./cmd/setup
go build -buildvcs=false -trimpath -o bin/test/detector-demo.exe ./cmd/detector-demo
```

这两个命令使用当前 Go 目标平台。跨平台构建时显式设置 `GOOS`、`GOARCH`，构建结束后恢复调用方环境。Detector Demo 图片通过 `go:embed` 内嵌，无需额外复制。

设备端 Agent 和 setUp 都使用本地 SQLite，保留纯 Go SQLite 依赖；Node 数据持久化使用管理平台原有数据库。旧 Cloud 二进制、旧 SQLite 数据和上传目录必须按迁移计划处理，不能继续作为独立服务启动。
