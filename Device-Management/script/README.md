# 本地数据库脚本执行清单

## 当前目标：平台注册/登录、项目、Node-Agent 联调

以下顺序适用于一个未初始化本平台结构的本地库。建议在 `127.0.0.1:5432` 新建专用 `equipmentManagement` 库，避免与当前 `postgres` 库里的其他项目表混用，然后修改私有 `api/agent-local.env` 的 `POMS_DB` 库名并重启 API。不要把旧建库脚本作为日常升级脚本在已有平台数据上重复执行。

| 顺序 | 文件 | 用途 |
| --- | --- | --- |
| 1 | `0.0.1/init_data.sql` | 旧平台基础结构，提供 `command_histories` 等下一步依赖；不是仅插入数据 |
| 2 | `0.0.1/2.create_table.sql` | 新账号/组织/部门/角色/资源/职位体系，默认组织和角色等初始化数据，以及项目、设备关系、系统日志 |
| 3 | `1.0.6/alter_table_projects.sql` | 增加 `projects.create_by`；外部注册用户的项目查询依赖这个字段 |
| 4 | `2.0.0/1.create_edge_cloud_management.sql` | 扩展 `project_devices`，创建视觉模型、升级任务、远程会话业务表 |
| 5 | `2.0.0/2.add_remote_session_recording.sql` | 增加远程会话录制列 |
| 6 | `2.0.0/3.node_agent_platform.sql` | Agent 设备、文件、任务等持久化记录及索引 |

第 2 步会替换第 1 步创建的旧账号/权限结构，存在 `DROP TABLE`，所以这是一条首次初始化链路，不是无损升级方案。第 4～6 步是增量迁移。文件名的 Cloud 历史命名不表示需要部署 Cloud。

本清单只覆盖当前 Agent 联调所需的 SQL 结构，不承诺平台全部历史页面可用。注册默认分配原有外部用户角色，不自动授予管理员或全部边缘管理权限；注册成功、角色配置及管理菜单是否可见是不同检查项。历史种子账号只提供密码摘要，不在此猜测明文密码。

## 以下文件不要与这条链路重复执行

| 文件 | 原因 |
| --- | --- |
| `0.0.1/1.结构+数据.sql` | 历史完整转储，包含大量旧业务数据和序列重置；与 `init_data.sql` 结构重叠 |
| `0.0.1/3.create_system_log.sql` | `2.create_table.sql` 已建 `system_log` |
| `0.0.1/4.alert_command_histories.sql` | `2.create_table.sql` 已加 `command_histories.operator` |
| `0.0.1/5.create_projects.sql` | `2.create_table.sql` 已建 `projects/project_devices/role_project` |
| `0.0.1/init_product_library_data.sql` | 产品库业务数据初始化，包含清理旧数据；Agent 联调不需要 |

## 其他业务功能的增量脚本

需要测试完整旧平台功能时，再按实际已有结构选择，不能把整个目录的文件全部运行。

| 目录 | 作用/依赖 |
| --- | --- |
| `1.0.5`、`1.0.8` | 旧传感器字典补充/名称更新 |
| `1.0.6/create_table_external_user_devices.sql` | 外部用户绑定旧设备，依赖平台 `user`；区别于 Node-Agent 设备登记 |
| `1.1.0` | 公式参数名称表，依赖 `formula` |
| `1.1.1` | 参数模板表、模板初始化数据、权限，按文件编号执行 |
| `1.1.2` | 蓝牙 APP 权限 |
| `1.1.9` | 添加设备型号权限 |
| `1.1.10` | 传感器字典数据；当前基础链路缺 `sensor_types.sensor_type`，这个脚本不能直接执行 |
| `1.1.11` | 参数模板历史及权限 |
| `1.1.12` | APP 应用/安装包及权限 |
| `蓝牙采集APPv1.2.4` | 蓝牙 APP 权限补充 |

完整增量顺序按版本数值排序：`1.0.5 → 1.0.6 → 1.0.8 → 1.1.0 → 1.1.1 → 1.1.2 → 1.1.9 → 1.1.10 → 1.1.11 → 1.1.12`，每个目录内按编号。权限/数据 INSERT 多数不防重复，已执行的不能盲目重跑。`1.1.10` 的缺列需要先核对正式库结构并补充相应迁移，本次未擅自选择列类型。

## 验证记录（2026-10-10）

上面的六步在本地 PostgreSQL 独立临时 schema 中顺序执行成功，最后全部回滚，没有初始化或修改真实平台业务结构。

额外尝试从基础结构按历史版本执行到 `1.1.10`：之前脚本通过，`1.1.10/insert_sensor_types.sql` 以 `42703` 报 `sensor_type` 列不存在；后续完整业务链路未在该试验中继续验证。不要把六步 SQL 通过等同于真实注册、登录和设备联调全部通过。

执行失败先看第一条错误；如果处于失败事务，先运行 `ROLLBACK;`。具体 `2.0.0` 前置检查见该目录 `README.md`。
